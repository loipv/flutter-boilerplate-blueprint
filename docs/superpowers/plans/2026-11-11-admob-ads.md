# Google AdMob Ads Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Google AdMob (banner, interstitial, rewarded, app open) with UMP/ATT consent to the blueprint, as an optional init feature that can also be switched off per build, from Remote Config, and per user.

**Architecture:**
- Feature module `lib/features/ads/` with four layers:
  - `domain/`: pure types and the `AdsRepository` interface.
  - `data/`: `GoogleMobileAdsGateway`, a logic-free SDK wrapper, and `GoogleMobileAdsRepository`, which holds the logic and is tested against a mocked gateway. These are the only files that import the SDK.
  - `application/`: providers combine the four on/off levels plus consent, pace full-screen ads, and react to app resume.
  - `presentation/`: the banner widget and the Settings privacy tile.
- `main.dart` only supplies build-time settings, through an `adsSettingsProvider` override.
- Ads start when `MainScaffold` first builds.

**Tech Stack:** Flutter, Riverpod 3 code-gen, `google_mobile_ads` (latest stable, bundles UMP), Mocktail.

**Spec:** `docs/superpowers/specs/2026-11-11-admob-ads-design.md`

## Global Constraints

- Commands: use `make` targets, otherwise `fvm flutter` / `fvm dart`. Never use bare `flutter`.
- Imports are absolute (`package:blueprint_app/...`). Log with `AppLogger`, never `print`. Use Lucide icons, `Gap(AppSpacing.pX)`, `ConsumerWidget` / `ConsumerStatefulWidget`.
- `google_mobile_ads` is imported only in `lib/features/ads/data/google_mobile_ads_gateway.dart` and `lib/features/ads/data/google_mobile_ads_repository.dart`.
- Marker name `ADS`, in the comment syntax of each file type:
  - `// BEGIN_ADS` in Dart and Gradle `.kts`;
  - `# BEGIN_ADS` in YAML, `.env` and the Makefile;
  - `<!-- BEGIN_ADS -->` in Markdown, XML and plist.

  No markers in `project.pbxproj` (Task 2 handles that file). Each marker line stands alone. Add `ADS_IMPORTS` to `featureRules` only if a file needs a separate imports block, as with `NOTIFICATIONS_IMPORTS`.
- Both variants must pass `make analyze` with no warnings: markers kept, and markers stripped (`--no-ads`).
- Coverage gate: `domain` 100%, `data` 90%, `application` 80%.
- One test file per source file, at the mirrored path (`make check-test-layout`).
- Test names follow `Given ..., When ..., Then ...`.
- Run `make codegen` after editing any `@riverpod` file.
- Values from the spec:
  - sample App IDs: Android `ca-app-pub-3940256099942544~3347511713`, iOS `ca-app-pub-3940256099942544~1458002511`
  - Google test ID prefix: `ca-app-pub-3940256099942544`
  - test ad unit IDs:

    | Format | Android | iOS |
    |---|---|---|
    | banner (adaptive) | `ca-app-pub-3940256099942544/9214589741` | `ca-app-pub-3940256099942544/2435281174` |
    | interstitial | `ca-app-pub-3940256099942544/1033173712` | `ca-app-pub-3940256099942544/4411468910` |
    | rewarded | `ca-app-pub-3940256099942544/5224354917` | `ca-app-pub-3940256099942544/1712485313` |
    | app open | `ca-app-pub-3940256099942544/9257395921` | `ca-app-pub-3940256099942544/5575463023` |

  - env vars: `ADS_ENABLED`, `ADS_DEBUG_GEOGRAPHY`, `ADMOB_{BANNER,INTERSTITIAL,REWARDED,APP_OPEN}_{ANDROID,IOS}`
  - Remote Config keys: `ads_enabled`, `ads_banner_enabled`, `ads_interstitial_enabled`, `ads_rewarded_enabled`, `ads_app_open_enabled` (bool, default `true`), and `ads_full_screen_min_interval_seconds` (int, default `90`)
  - app open cache lifetime: 4 hours
  - app open resume guard: no app open within 5 seconds of any full-screen ad closing, whatever the Remote Config interval
  - no-fill load error code: `3` (log `warning`; other codes log `error`)

## Review Focus

1. A full-screen ad whose `show()` fails (`shown: false`) must not leave the controller stuck "showing", must not count toward the cap, and must still reload the slot. Covered in Tasks 4 and 7.
2. The app resumes while a full-screen ad is still on screen (e.g. the user tapped the ad, visited the browser, came back). App open must not stack on top. Covered in Task 7.
3. `AdBanner` unmounts, or ads switch off, while a banner load is still in flight. The late handle is disposed, with no `setState` after dispose and no leaked ad. Covered in Task 8.
4. Consent drops to `canRequestAds: false` mid-session (privacy options form). The banner disappears, and the cached interstitial is not shown. Covered in Tasks 6 and 8.
5. A negative `ads_full_screen_min_interval_seconds` from Remote Config is treated as 0, not as "never show". Covered in Task 7.

- Produces, in `google_mobile_ads_gateway.dart` (first line `// coverage:ignore-file`; logic-free; it only turns SDK callbacks into Futures and exceptions):

  ```dart
  class GoogleMobileAdsGateway {
    Future<void> requestConsentInfoUpdate({required bool debugGeographyEea});
    Future<void> loadAndShowConsentFormIfRequired();
    Future<void> showPrivacyOptionsForm();
    Future<bool> canRequestAds();
    Future<bool> privacyOptionsRequired();
    Future<void> initializeSdk();
    /// Throws [AdLoadException].
    Future<AdBannerHandle> loadBanner({required String adUnitId, required double width});
    /// Throws [AdLoadException]. [format] is interstitial, rewarded or appOpen.
    Future<LoadedAd> loadFullScreen(AdFormat format, String adUnitId);
  }

    /// Completes when the ad is dismissed or fails to show.
    Future<AdShowResult> show();
    void dispose();

  class AdShowResult {
    const AdShowResult({required this.shown, this.reward});
    final bool shown;
    final RewardEarned? reward;
  }
  class AdLoadException implements Exception {
    const AdLoadException(this.code, this.message);
    final int code;
    final String message;
  }
  ```
